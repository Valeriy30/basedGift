Мини-приложение «basedGift»

Версия: 2026
Платформа: Base (строгое соответствие https://docs.base.org/get-started/base
)

1. Общие сведения
1.1 Назначение системы

Мини-приложение «basedGift» предназначено для отправки цифровых подарков (USDC и NFT) пользователям сети Base посредством уникальной ссылки с автоматическим зачислением средств напрямую на основной кошелек получателя без создания промежуточных аккаунтов.

1.2 Цели проекта

Обеспечить gasless-получение подарка для получателя.

Обеспечить максимально простой онбординг новых пользователей Base.

Исключить фрагментацию балансов и временные кошельки.

Повысить эмоциональную ценность транзакций за счет визуального и мультимедийного оформления.

2. Функциональные требования
2.1 Пользовательские роли

Отправитель — пользователь сети Base, имеющий кошелек с USDC и/или NFT.

Получатель — любое физическое лицо, перешедшее по ссылке, вне зависимости от наличия Base App на момент перехода.

3. Пользовательские сценарии (User Flow)
3.1 Сценарий отправителя
3.1.1 Выбор подарка

Отправитель должен иметь возможность:

указать сумму в USDC

выбрать NFT, принадлежащий его кошельку

3.1.2 Кастомизация оформления

Система должна поддерживать:

выбор визуальной темы (минимум):

«С днем рождения»

«За кофе»

«Просто так»

«Благодарность»

ввод произвольного текстового сообщения

добавление:

аудио-сообщения

стикера

добавление фонового изображения или видео

3.1.3 Создание ссылки

После подтверждения:

выбранные активы депонируются в смарт-контракте (escrow)

генерируется уникальная ссылка формата deep-link

отправитель оплачивает газ за получателя через Paymaster (ERC-4337)

3.2 Сценарий получателя (Seamless Claim)
3.2.1 Переход по ссылке

ссылка должна открываться:

в Base App (приоритетно)

во встроенных браузерах мессенджеров (Telegram, WhatsApp, Farcaster)

3.2.2 Экран подарка

При открытии отображается:

анимированная страница

выбранное отправителем оформление

персональное сообщение

3.2.3 Получение подарка (Claim)

На странице должна быть одна кнопка:
«Забрать на мой кошелек»

При нажатии:

пользователь аутентифицируется через:

Base App

Passkeys (FaceID / Fingerprint)

смарт-контракт автоматически переводит средства на основной адрес пользователя

запрещено хранение средств на временных адресах

3.2.4 Отсутствие Base App

Если Base App отсутствует:

система предлагает создание кошелька в 1 клик через биометрию

после создания средства автоматически зачисляются на новый основной адрес

4. Техническая архитектура
4.1 Фронтенд

Framework: React.js или Next.js

Язык: TypeScript

Требования:

Mobile-first дизайн

оптимизация под WebView Base App

поддержка анимаций и мультимедиа

4.2 Взаимодействие с блокчейном Base

Библиотеки:

Wagmi

Viem

SDK:

OnchainKit (Coinbase)

Подключение кошельков:

RainbowKit

встроенные коннекторы Base App

4.3 Смарт-контракты

Язык: Solidity

Среда разработки: Foundry (предпочтительно) или Hardhat

4.3.1 Функции контрактов

депонирование USDC и NFT

валидация claim-операции

перевод активов напрямую на основной кошелек получателя

поддержка emergency-withdraw

4.3.2 Требования

использование библиотек OpenZeppelin

совместимость с ERC-4337

ограничение максимальной суммы подарка (на старте)

4.4 Бэкенд и инфраструктура (опционально)

Среда: Node.js (TypeScript)

Индексация: The Graph или Goldsky

Хранение данных:

IPFS или Arweave (метаданные, оформление)

5. Account Abstraction и Paymaster

обязательная поддержка ERC-4337

Paymaster оплачивает газ получателя

поддержка:

нескольких Paymaster-провайдеров

автоматического fallback

наличие функции Emergency Exit с обычной транзакцией

6. Соответствие гайдлайнам Base

Система должна строго соответствовать:

Gasless-получение

Mobile-first

Интеграция с социальным графом (Farcaster)

Использование компонентов OnchainKit

Поддержка Base Names

7. Нефункциональные требования
7.1 Безопасность

обязательный независимый аудит (CertiK / SlowMist или аналог)

защита от повторного claim

защита от reentrancy и logic-flaws escrow

7.2 Приватность

минимальный сбор данных

шифрование личных сообщений

прозрачная политика приватности

8. Анализ рисков и меры снижения
8.1 Фишинг

Меры:

официальная верификация в Base App

deep-link с приоритетом Base App

пользовательское образование

8.2 Уязвимости escrow

Меры:

аудит

лимиты сумм

проверенные библиотеки

8.3 Отказ Paymaster / AA

Меры:

резервные Paymaster

emergency-withdraw

8.4 Ошибочная отправка

Меры:

двойное подтверждение получателя

функция тестовой отправки (1 USDC)

9. Ожидаемый результат

В результате реализации должно быть создано мини-приложение Base-экосистемы, позволяющее безопасно, бесшовно и эмоционально отправлять цифровые подарки с нулевой комиссией для получателя и автоматическим зачислением на основной кошелек.
